# Аналитика переписок

Локальное приложение анализирует экспорт Telegram и показывает пять самых частых тематических групп диалогов. У каждой темы выводится число сессий и три примера разговоров.

## Что умеет

- Парсит Telegram JSON export.
- Считает количество сообщений, пользователей и диалоговых сессий.
- Показывает активность по часам и дням недели.
- Делит переписку на сессии по паузе между сообщениями.
- Строит признаки сессий: длина, длительность, темп, автор начала диалога.
- Кластеризует сессии по поведенческим признакам через KMeans и просит локальную LLM интерпретировать группы.
- Визуализирует кластеры через UMAP.
- Группирует диалоговые сессии по локальным эмбеддингам.
- Показывает пять крупнейших тематических групп, число сессий в каждой и три примера.

## Установка

Проект рассчитан на Python 3.10+.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Запустите приложение Ollama, затем один раз скачайте embedding-модель (веса модели хранятся локально отдельно от данных переписки):

```bash
ollama pull qwen3-embedding:0.6b
# Проверь, что генеративная модель тоже установлена:
ollama list
```

## Локальный запуск

Создайте отдельное Python-окружение проекта и установите зависимости:

```bash
make install
npm --prefix frontend install
```

## Запуск приложения

```bash
make app
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Интерфейс и API обслуживаются одним локальным процессом; оставьте терминал открытым во время работы. Перед запуском `make app` соберёт frontend.

До старта приложения убедитесь, что Ollama работает локально и `ollama list` показывает `llama3.1:8b`. В интерфейсе семантическую и поведенческую кластеризацию можно запускать независимо. Семантическая кластеризация использует MiniBatchKMeans по локальным эмбеддингам и показывает пять крупнейших тем с примерами. Поведенческая кластеризация использует KMeans по метрикам сессий; локальная LLM получает только агрегированные метаданные групп и описывает их по длительности, объёму и темпу общения — без текстов сообщений. Модели можно переопределить через `TOPIC_EMBEDDING_MODEL`, `TOPIC_LABEL_MODEL` и `BEHAVIOR_LABEL_MODEL`.

## Формат входных данных

При загрузке экспорт разбивается на сессии: новая начинается, если между сообщениями прошло больше 30 минут. «Количество упоминаний» считается как число сессий, отнесённых к теме, а не как число отдельных словоупоминаний. Тексты и эмбеддинги остаются в памяти процесса; после остановки приложения они исчезают.

Ожидается JSON export из Telegram со структурой:

```json
{
  "messages": [
    {
      "id": 1,
      "type": "message",
      "date": "2026-01-01T12:00:00",
      "from": "User name",
      "text": "Message text"
    }
  ]
}
```

Поле `text` может быть строкой или списком Telegram text entities. Парсер приводит оба варианта к обычной строке.

## Приватность данных

Файлы реальных переписок не входят в репозиторий. При локальном запуске файл остаётся на компьютере и передаётся только локальному процессу приложения.

## Быстрая проверка пайплайна

Если в папке `Переписки/` есть тестовый JSON, можно проверить базовую обработку без запуска UI:

```bash
python -c "import json; from base.pipeline import process_chat; data=json.load(open('Переписки/result_kotik.json')); stats, clusters, amount, umap, topics = process_chat(data, include_umap=False); print(stats['overview']); print(amount.to_dict())"
```

Построение эмбеддингов и названий тем может занять время на большом экспорте; тексты отправляются только локальному Ollama на этом компьютере.

## Текущие ограничения

- Количество кластеров KMeans сейчас фиксировано: `4`.
- UMAP и KMeans используют фиксированные параметры, которые стоит адаптировать для маленьких чатов.
- Медиа, стикеры и сообщения без текста попадают в общую статистику как сообщения с пустым текстом.
